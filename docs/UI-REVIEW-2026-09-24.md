## Product and interaction findings

### 1. The primary view does not convey timing or overlap

**Priority: P1 — core product requirement. Browser-confirmed.**

`web/src/execution/SampleLanes.tsx:49` renders a horizontal list of accumulated scheduled-token chips. There is no shared elapsed-time axis, planned/observed arrival marker, waiting interval, or alignment of execution steps across rows. Every sample's first chip starts at the same position even when the samples arrived at different times.

In the actual GPU recording, execution steps 6–8 mix samples from arrival batches A and B, and step 9 includes samples from B and C. Those relationships are available in the data, but cannot be read directly from the lane geometry.

**Fix:** Add a shared time ruler and position evidence-backed milestones/host intervals consistently across sample rows. Alternatively provide an explicitly labeled step-aligned view as a second mode. Show planned and observed arrivals separately, mark the selected step across participants, and retain token ranges as details. Do not depict host intervals as GPU kernel measurements.

The visual treatment is substantially closer to the reference, but still feels like a dense form and trace table. The largest improvement now comes from the visualization itself, followed by tighter composer cards and smaller step cards.

### 2. Editing sample labels opens a modal and steals focus

**Priority: P1 — blocks ordinary authoring at compact widths. Browser-confirmed.**

Reproduction at 1280px width: click the `input_1` display-label field. The Inspector dialog opens and focuses Close inspector immediately, instead of allowing the name to be edited.

Cause: `web/src/scenario/SequenceComposer.tsx:252` selects the sample on input focus; `web/src/App.tsx:310` opens the inspector for compact selections; the effect at line 245 calls `showModal()` and focuses its first button.

**Fix:** Separate passive selection/highlighting from explicit inspector opening. Focusing an editable field must not open a modal. Add browser coverage below and above the 1280px breakpoint.

### 3. Common laptop heights push primary controls far below the viewport

**Priority: P2 — significant usability regression. Browser-confirmed.**

At 1280×720, the page was approximately 1,618px tall. Run sequence began around y=1,286 and the playback transport around y=1,487. The center acquires a large unused vertical area while the long composer determines the page height.

`web/src/styles.css:413` changes the shell to automatic height and removes overflow containment for viewports no taller than 760px.

**Fix:** Keep the workspace bounded to the viewport and scroll the composer and sample area independently. Keep Run sequence reachable in a composer footer and the playback transport visible. Test 720px-high windows explicitly.

### 4. Inspector timestamps are difficult to compare with planned arrivals

**Priority: P2 — undermines the timing explanation. Browser-confirmed.**

For input_4 the inspector displayed requested arrival `100 ms`, scheduler receipt `7011402919429 ns`, and controller return `7011402937854 ns`. Its scheduler receipt was approximately 105ms after the recorded origin, which is the useful comparison.

`web/src/execution/SelectionInspector.tsx:127` and line 131 format raw monotonic values in the primary inspector.

**Fix:** Show elapsed milliseconds relative to the recorded controller origin, with named observation types. Put raw clock values under technical details. Preserve the legacy-recording time-basis label when an origin is unavailable.

## Live execution findings

### 5. The controller origin is unavailable throughout live capture

**Priority: P1 — prevents accurate live alignment. Reproduced in an isolated backend test.**

`runner/serve.py:504` passes a local origin object into `drive_run`, but copies it into `state.origin` only after `drive_run` returns at line 521. During an active blocked step, arrivals were already published while both current/trace metadata still had a null origin. The origin appeared after completion.

**Fix:** Publish the origin at execution start, before admission begins, through an explicit callback/shared snapshot. Verify that live and finalized views use the same time basis.

### 6. Live updates rebuild the complete replay player

**Priority: P2 — causes growing interaction stalls. Source review plus local synthetic benchmark.**

`web/src/App.tsx:161` calls `createPlayer(events, manifest)` whenever the live event list or provisional metadata changes. It rebuilds the entire checkpoint history on the browser's main thread.

A local valid synthetic eight-sample trace took approximately 168ms at 32 output tokens, 623ms at 64, and 2,459ms at the allowed 128 tokens (2,440 events) for one rebuild. These are local measurements, not universal performance claims. They exceed the 400ms polling cadence at larger allowed workloads.

**Fix:** Append events/checkpoints incrementally, preserve stable metadata references where possible, and test interaction responsiveness at the supported request/output limits.

### 7. Run-view identity is not maintained across reload and close

**Priority: P2. Source-confirmed; not exercised through a fresh live browser run.**

- Reload during an active run: `web/src/App.tsx:131` requires a nonempty matching `expectedRun`, but that ref is only set by the current page's POST response at line 357. The trace hook can fetch data while the view remains a draft. Restore/adopt the active run with its submitted plan, or offer Resume live run.
- Close a run completed in this page: `web/src/App.tsx:446` clears `recording` but retains the expected run ID and finalized trace. `showingLive` becomes true again, so the capture remains visible instead of returning to the draft. Clear the displayed live-run identity as part of closing.

### 8. Simultaneous trace readers can skip records

**Priority: P2 — trace integrity with multiple clients. Reproduced in an isolated concurrency probe.**

`runner/trace_index.py:33` reads and mutates the shared byte offset, seen set, and records without synchronization. Forced simultaneous reads doubled a single record's byte offset. After subsequent records were appended, a later page omitted sequence 2 and returned sequence 3.

**Fix:** Synchronize refresh and page snapshots per index. Add an overlapping-client test, rather than only sequential cursor retries. Do not silently accept missing sequence continuity.

## Additional correctness issues for the follow-up

These are narrower than the primary experience gaps, but should be addressed with focused regression tests:

1. **Future observation leakage:** `replay/src/timeline.ts:254` exposes admission-call return as soon as request state exists. An isolated prefix ending at 1ms displayed a return at 2ms. Gate the observation on prefix time or an appropriate event.
2. **Structural export retains token content:** `runner/serve.py:594` adds `engine_output_token_ids` to the manifest; `runner/export.py:16` copies it into structural exports. A probe with `content_retained: false` still contained output token IDs. Remove them from structural exports or keep them exclusively in content storage.
3. **Engine failure loses finalized arrival metadata:** `runner/serve.py:504` assigns arrivals/tokens only on successful return. After a later step failed, a probe's live state retained text and one arrival, while the finalized manifest had empty arrivals and output IDs. Use incrementally preserved progress during failure finalization.
4. **Strict validation is bypassed by coercion:** ordinary Pydantic integer fields in `runner/serve.py:68` convert booleans/strings/integral floats before Add now validation. Use strict fields or validate raw inputs consistently with initial requests.

## Recommended completion order

1. Fix label focus and 720px-height control visibility.
2. Implement a shared sample timeline and elapsed-time inspector values.
3. Publish the live origin immediately; fix run-view identity and trace-index concurrency.
4. Replace repeated full replay construction with incremental state/checkpoints.
5. Address the smaller prefix/export/failure/validation cases and add browser tests for the interactions missed by the passing unit tests.

Keep the successful composer model, exact offset serialization, immutable submitted metadata, fixture/GPU distinction, recorded sample inspection, and backward-seek output behavior.
