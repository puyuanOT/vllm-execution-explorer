# GPU acceptance: `run-42f3805f07c3`

This bundle preserves the structural evidence from a completed UI-driven GPU
capture. The explorer copied an operator-local OPT-125M checkpoint to a remote
Ubuntu execution host, prepared vLLM, ran the workload through its instrumented
loopback HTTP boundary, finalized the recording, and opened it in Explore.

## Captured environment

- GPU: NVIDIA A10
- Engine: vLLM 0.30.0
- Explorer adapter: `vllm_030` 0.2.0
- Model: OPT-125M from an execution-host path, with `dtype=auto` and no
  quantization
- Engine settings: prefix caching and chunked prefill enabled; maximum four
  active sequences and 32 scheduled tokens per step
- Sampling: temperature 0, top-p 1, seed 0, eight output tokens per request
- Workload: six requests in three batches at 0 ms, 100 ms, and 1500 ms

The run completed with 270 ordered events, six request completions, 27 scheduler
steps, 48 accepted tokens, and 32 KV-block transitions. Those transitions
include 13 allocation transitions across 11 block IDs. HTTP receipt and engine
admission were observed for every request. The manifest records GPU acceptance
as passed, while its provisional workload ceilings remain explicitly unvalidated.

A LoRA adapter was available in the engine configuration, but every request in
this particular workload used the base route. This bundle therefore does not
serve as LoRA-routing acceptance evidence. It also contains no CUDA-kernel trace
or instrumentation-overhead measurement.

## Files

- `manifest.json` is the sanitized structural manifest.
- `events.jsonl` is an unchanged copy of the 270-event structural stream.
- `integrity-report.txt` is generated by `runner.report` with the `integrity`
  profile.
- `SHA256SUMS` authenticates the three evidence files above.

## Sanitization

The bundle was created with `runner.export.export_structural`. It does not
include the source `content.jsonl`, which held prompt text, generated text, and
token ID payloads, and the exporter removes content-bearing manifest fields
such as `engine_output_token_ids`. Absolute execution-host model/cache paths
were then replaced by stable aliases. Structural token counts, ranges, request
IDs, timestamps, and content references remain because they describe execution
without making content recoverable.

The SSH destination, private-key path and bytes, and any Hugging Face token are
absent. `manifest.json` records the source manifest's SHA-256 digest so the
sanitized copy can be associated with the original in a controlled environment
without retaining it here. The configuration snapshot digest is preserved from
the source and therefore describes the original pre-sanitization configuration.

## Validation

```bash
recording = load_recording(Path("docs/acceptance/run-42f3805f07c3"))

print(report.text(), end="")
raise SystemExit(0 if report.ok else 1)
PY
```

The expected result is eight passing integrity findings and `Result: pass`.
